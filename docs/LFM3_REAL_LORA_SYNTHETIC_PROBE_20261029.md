# LFM3-1.7B real-checkpoint LoRA probe — synthetic tokens only

Date: October 29, 2026. Node: x1-370. Research branch based on pinned-loader draft PR #68. **No production changes or weight promotion**.

## What was actually executed

A genuine official-pretrained LiquidAI/LFM3-1.7B BF16 model was loaded using the strict local checkpoint/source hash verifier and the reviewed Transformers 5.17 compatibility handling. It was run CPU-only, offline, with all GPU-visible environment flags set to -1.

PEFT rank-2 adapters were attached to q_proj and v_proj in the attention layers. Exactly 44 adapter tensors (146,432 scalar parameters) were trainable. The 1.728B-parameter pretrained backbone remained frozen. No resulting adapters or modified model weights were written to disk, transferred to a production trainer, or promoted.

The probe generated **synthetic random token IDs**, not actual text or private traces: 16 training sequences of length 12 and four disjoint held-out sequences per seed. With three seeds (1,2,3), each optimizer received 20 actual forward/backward/update steps at learning rate 0.0001. Each optimizer arm reloaded the same pinned original model and generated the same initial adapter tensors and dataset for its seed. Muon was restricted to LoRA matrices and required a separate experimental flag. This does **not** qualify those factors as generally appropriate Muon groups; AdamW remains the default production proposal.

## Held-out teacher-forced loss (lower is better)

| Seed | Initial loss (both arms) | AdamW final | Experimental Muon final |
|---|---:|---:|---:|
| 1 | 12.66598 | 12.62762 | 12.63783 |
| 2 | 13.63903 | 13.59523 | 13.57866 |
| 3 | 13.14442 | 13.10152 | 13.11877 |
| Mean | 13.14981 | 13.10812 | 13.11176 |

Both optimizers achieved a small reduction in this artificial loss. AdamW had lower final loss on two seeds; experimental Muon on one. The mean difference is about 0.00364 loss units in AdamW's favor. This is **not** a statistically meaningful claim about optimizer superiority, model quality or useful fine-tuning. Synthetic random-token teacher-forced loss does not establish improved language abilities. The same heldout sequences were used for reporting the comparison and are **not fresh independent model-selection evidence**.

Measured optimizer-step durations (not standardized throughput): mean 10.58 seconds per 20-step AdamW run versus 10.49 seconds per 20-step Muon run; these ignore model loading, evaluation and some overhead. Wall-clock full comparison was approximately 89 seconds. Do not cite these as fleet GPU performance.

## Provenance and safety

The report in research/evidence/lfm3-real-lora-20261029 includes all **120 real optimizer-step telemetry records**, unique execution IDs, training and heldout SHA-256 digests, initial/final adapter SHA-256 fingerprints, loss measurements, and sampled frozen-backbone checks. The reviewer rejects mixed initial weights, mismatched data, malformed or incomplete telemetry, invalid loss values and any promotion claim. The result is explicitly labeled real pretrained model / synthetic tokens / no private traces / non-production / weight promotion disabled. A full frozen-backbone file-level comparison is unnecessary here because the only optimizer parameters are verified LoRA tensors, the original verified checkpoint remains on disk, and a frozen backbone sample is checked after each run.

## Reproduction

Only run in a disposable environment with the verified official model files and an isolated Transformers 5.17+tokenizers 0.23.3 overlay. On x1-370, from repository root:

~~~sh
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
CUDA_VISIBLE_DEVICES=-1 HIP_VISIBLE_DEVICES=-1 ROCR_VISIBLE_DEVICES=-1 \
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 \
PYTHONPATH=/home/scott/lfm3-research/isolated-transformers-5.17.0:$PWD \
/home/scott/venv-rocm/bin/python -m src.lfm3_real_lora_probe \
  --research-only --allow-real-lora-training \
  --allow-experimental-muon-lora --optimizers adamw muon \
  --model-path /home/scott/lfm3-research/model-metadata \
  --seeds 1 2 3 --steps 20 --adamw-lr 0.0001 --muon-lr 0.0001 \
  --output /tmp/unique-new-probe-output.json

python3 -m src.lfm3_real_lora_review /tmp/unique-new-probe-output.json
~~~

The output file uses exclusive creation and will not overwrite an existing experiment. CPU-only/offline flags are checked before loading; the optimizer configuration is bounded and Muon requires explicit experimental opt-in. The model is verified against the official pinned revision before each arm. No network downloads, GPUs, live fleet training jobs, model promotion, or server configuration changes occur.

## Independent execution repeatability (seed 1)

A second, separately launched CPU-only run of seed 1 at 20 steps per arm was compared with the original paired run. Both AdamW and experimental Muon produced **exactly the same initial adapter SHA-256, final adapter SHA-256, final held-out loss, and full 20-step training-loss trajectory**. Each execution correctly received a different run ID. The second set of full telemetry and a SHA-256-backed comparison summary are committed in the same research/evidence directory. This confirms deterministic replay of this narrow CPU configuration; it is not an independent new task-quality evaluation or evidence of a general optimizer advantage.

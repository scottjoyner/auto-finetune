# Fabricated two-case LFM3 answer-level A/B (2026-10-27)

**Scope:** real BF16 weights, on xwing CPU, isolated network-disabled and read-only model sandbox. All task facts and session IDs are fabricated. No traces, no live SensorGraft graph query, no training, and no production processes modified.

## Reproducible files

- Runner: `src/lfm3_fabricated_ab.py`
- Lab cases: `research/fixtures/lfm3_fabricated_two_case_v1.json`
- Output: `research/results/lfm3_fabricated_two_case_ab_20261027.json`
- Gate plans are generated by SensorGraft `sg_lfm3_gate_plan --synthetic-only`, with exact plan digests in the receipt. Both source and zero plan share the synthetic activation fingerprint.

Pinned model revision: `40ebe0aa6662c9d40389c2f5d565b6a2c6aebacd`; BF16 SHA-256 `135922caef64e81e52af88ede8b7c3ddaa9d6da220a9737fb3065275dbfb4330`. The runner calls the offline SHA-256 attestor before loading. Transformers 5.21.0 + CPU PyTorch 2.14.1 were tested. Each condition uses the same model, seed, hardware and maximum **40** generated tokens; no decoding samples are used. All case text and model responses stay inside the sandbox process.

**Important model behavior:** LFM3's official pinned `chat_template.jinja` has `enable_thinking` defaulting to true. With that default, all eight generations consumed the 40-token budget without exact-answer matches. The controlled comparison therefore explicitly uses `enable_thinking=False` for short exact-answer tasks, held equal across all four conditions.

## Exact outcome, two fictional cases

| Condition | Dev (n=1) | Heldout (n=1) | Total |
| --- | ---: | ---: | ---: |
| Baseline/no reference | 0 | 0 | 0/2 |
| Supplied synthetic reference text | 1 | 1 | 2/2 |
| Synthetic head gates only | 0 | 0 | 0/2 |
| Reference text + synthetic head gates | 1 | 1 | 2/2 |

This is an **extremely small illustrative smoke test**, not a reliable effectiveness study. The retrieval-labeled condition uses a supplied fictional reference string, not a query against SensorGraft, Neo4j, or the trace viewer. The head-gate controller is deterministic and NOT trained. Adding synthetic gates showed **no additional exact-answer benefit** on these cases.

The receipt includes observed per-condition latency and tokens. It must not be interpreted as fleet benchmark throughput, energy, p95 latency (each split contains only one case), or quantitative causal evidence about any real trace source. Comparisons are sequential and may be affected by thermal/load state. The existing evaluator's `checkpoint_cryptographically_attested=false` field means its *result rows* are self-asserted; the separate runner did verify the actual pinned checkpoint assets before inference.

## Authority and CI

The cross-repo boundary intentionally refuses the SensorGraft `sg-lfm3-shadow-features.v1` metadata artifact as a head gate plan. Unverified source metadata cannot be silently upgraded to neural control or ground truth.

Full GitHub test coverage remained below the enforced 69% threshold in earlier runs; the gate remains unchanged. Keep the PR draft/unmerged, with no production graph migration, model release or training on traces.
